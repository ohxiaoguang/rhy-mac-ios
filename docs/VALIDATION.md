# 验证范围

## 0.3.0：启动设置、方向按键与 FPS

新增双端启动页的掌机／底座选择及 FPS 显示开关，保存到各平台本机偏好。iOS 左侧虚拟摇杆改为上下左右方向按键；多点触控、滑出释放及触摸取消均走按键状态路径，不再输出虚拟摇杆轴。

- Mac 与 iOS Rust 核心检查、双端 Swift 启动页类型检查通过；原有 19 项单元／协议回归通过。
- 实际操作 Mac 启动页选择底座、勾选 FPS，再退出并重新打开，确认两项设置保持；之后恢复默认掌机模式和关闭 FPS。
- Mac 底座模式宿主运行检查中，实际游戏窗口的原生标签显示约 `60.0 FPS`；关闭 FPS 后另起掌机模式进程，确认窗口不再出现该标签。
- 新版 iOS IPA 完成构建与开发签名校验；新增方向按键的真机手感、设置交互及 FPS 画面仍待设备复测，不沿用 0.2.0 的用户验收作为新布局的实测结论。

本次构建前用户已删除编译缓存，已重新生成。原始资源目录移动后，根据 Mac 启动页中已保存的新位置恢复了本地链接；原始文件未改动。运行记录和安装包仍只保存在忽略的本地目录，不进入源码仓库。

## 图形、帧率与声音

修复了观察到的 BC7 图集错位和换页叠字，已观察的菜单、引导和 Mac 首关画面未见同类错误。NVN acquire 限制 CPU 提交速率，默认便携模式为 60 Hz。

Mac 约 10 分钟诊断运行的每秒帧率中位数为 60，均值约 59.25；期间每 5 秒同步编码 PNG，并有并行编译。常规重启检查区间约 59.9–60.1 fps。不能将同步截图造成的低点直接等同于正常游玩帧时间。

iPad 约 70 秒运行的帧率中位数为 60，均值约 59.47，最低 48.5；期间同步转存四张 PNG，并有首次加载停顿。

音频使用游戏自带 SDK 的 CPU/manual 渲染流程，宿主将混音结果送入 Core Audio：

| 本地采集 | 格式 | 峰值（PCM16） | 削波占比 |
| --- | --- | --- | --- |
| Mac 正式关卡 20 秒片段 | 48 kHz / 双声道 | 13,096 | 0 |
| iPad 启动及引导 70.31 秒 | 48 kHz / 双声道 | 9,326 | 0 |

Mac 后续回归的缓冲不足计数保持启动预填的 3 块；iPad 诊断运行记录 40 块，集中于启动、首次加载及诊断期间，后段未持续增长。非静音、无削波不等于完整听感或音画延迟测量；仍需针对正常关卡场景继续检查。
